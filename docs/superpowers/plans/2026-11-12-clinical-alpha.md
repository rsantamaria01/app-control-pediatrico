# Clinical Alpha Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Raul authorized commits/PRs for the design handoff and later reviewed implementation slices; commit/push only the intended approved slice after its independent review gates. Do not implement in the current handoff task.

**Goal:** Deliver the entire accepted design board as a working phone-and-desktop alpha for the pediatrician: verified WHO 2006 growth, doctor/parent/PDF, agenda/assistant/public booking, draft-labelled sourced preventive catalogs, reminders, admin/audit and PWA; no fake screens.

**Architecture:** One Nuxt app, one database per clinic; server-side authorization precedes clinical reads. Import verified WHO 2006 datasets with immutable per-measurement result snapshots, then expose role-filtered API projections to doctor and parent screens. Alpha uses WHO corrected age for preterm children (no Fenton), provisional clinical copy/labels, manual clinician-marked trend and a doctor-approved report snapshot. Continue from this demoable growth foundation through the complete board in vertical slices; seed preventive catalogs as conspicuously unreviewed drafts from official sources, and run notification channels without invented credentials or delivery.

**Tech Stack:** Nuxt 4 (compatibilityVersion 5), TypeScript, Nuxt UI v4, Drizzle/PostgreSQL 18, Better Auth username plugin + email-and-password (verify installed Nuxt integration), ECharts 6/vue-echarts, Zod, RustFS for approved PDFs if needed, @vite-pwa/nuxt, Vitest, Playwright. Installed dependencies are in `package.json`; Better Auth and email transport are not yet installed. Check versions/APIs with Nuxt/Nuxt UI/Context7 at execution time; do not guess library integration.

**Spec:** `docs/superpowers/specs/2026-11-12-first-release-design.md` and accepted `docs/decisions/2026-11-10-ui-and-clinical.md`; clinical inputs `docs/clinical/2026-11-10-pediatrician-data-requirements.md`. Illustrative board and screenshots: `docs/design/README.md`.

## Global Constraints

- Every displayed LMS/SD reference is official, source/version/dated and validated against WHO Anthro before patient use; never copy the fictional design curves.
- First alpha: age 0–5 WHO 2006 only, both sexes strictly filtered, length/height position and 0.7 cm adjustment verified; ages 5–19 say `No disponible` for growth Z/curves.
- Corrected age through 24 chronological months, extended individually through 36 months for extreme preterm; Fenton deferred provisionally pending pediatrician alpha review.
- WHO disjoint-regression correction beyond ±3 stays intact in `shared/utils/zscore.ts`; classification uses **unrounded** Z and strict `<`/`>` at ±2/±3.
- Provisional labels add `Talla alta para la edad` at HFA Z > +2 and `Microcefalia severa` at HC Z < −3; keep `Riesgo de sobrepeso` wording. Centralize all labels/thresholds in one table-driven module; review at alpha demo.
- Parent copy follows C10 in one copy/config point (`dentro / fuera del rango esperado`, reassuring doctor title); percentile displayed beside Z for clinician, guardian and PDF; pediatrician reviews both at alpha demo.
- Seven sex-specific SD curves with −2…+2 shading, fixed patient blue, end labels, accessible measurement table; light/dark, 375/1024/1440px and `es-EC` decimal comma with true minus U+2212.
- Four roles (`ADMIN`, `DOCTOR`, `ASSISTANT`, `PATIENT`); assistants only get child name, guardian contact and invite status for grants, never clinical data; parents only their verified children; every clinical doctor read is audited.
- Sign-in for every role is username + password using Better Auth username plugin and email/password, **no email-OTP sign-in** and no self sign-up. The accepted AuthMobile/Login1440 artboards are layout references only; superseded OTP sign-in copy and controls must not ship. Usernames normalized lowercase, unique case-insensitively, 3–32 `[a-z0-9._-]`. Passwords ≥10 chars, no composition rule, reject local common/breached list; Better Auth default hash and UI strength hint. Valkey per-username AND per-IP rate limit, progressive delay/temporary lockout, generic `Usuario o contraseña incorrectos`, failed-attempt audit. Recovery accepts username/email and emails a one-use 10-minute code/link with identical generic response for existing/missing and successful/failed delivery, redacted structured failure event + persisted audit/health record, resend cooldown. Staff sessions 12h, parents 30d; password changes revoke other sessions; 7-day invitation setup chooses username/password; never grant access from booking contact. No clinical API or authenticated HTML in service-worker caches or static prerender; `/api/**` is NetworkOnly.
- Doctor must preview and explicitly approve **each** PDF; approved snapshot immutable and never includes private notes, differential diagnoses or confidential administrative fields.
- The alpha includes working booking, vaccine, milestone, agenda, reminder and admin screens; navigation to a slice is enabled only when its flow passes end-to-end tests. Seed preventive entries from original official WHO/CDC/AAP/MSP documents with source/version/date and visible `Borrador · pendiente de revisión pediátrica` on every draft entry; draft advice must never look definitive. Reviewed catalog status is a real-release gate, not an alpha-demo prerequisite. Alpha may use real identifiable child data under Raul's explicit accepted legal-draft pilot risk only after clinical/security/rights verification gates pass; the demo may instead use fictional patients with real WHO reference tables.
- Each task uses TDD: failing focused test → confirm failure → smallest implementation → targeted pass → `pnpm lint && pnpm typecheck && pnpm test && pnpm test:integration` (from Task 2); use Playwright on real flows. `pnpm test` currently includes only `test/unit/**/*.test.ts`; wire integration tests into a separate runner command/config with isolated disposable Postgres before treating them as passing. Each reviewed task may be committed on its slice branch only when Raul's approved gates pass; never merge `feat/alpha` to main without Raul.

## Review Focus

1. A 5+ year-old or an out-of-range age/position/reference lookup must show unavailable, never silently use a wrong WHO table — Task 4 test.
2. A second child's guardian and an assistant guessing a patient URL must get a denied response with no clinical fields — Task 7 test.
3. An exactly ±2/±3 raw Z that rounds across a boundary must retain the strict, unrounded classification — Task 5 test.
4. A preterm child crossing 24/36 months must switch age basis as decided and retain it in the original snapshot — Task 6 test.
5. A family PDF rendered after a private note changes must remain the approved, sanitized version — Task 9 test.

Seed only fictional patient identities for automated tests; WHO rows must be verified official rows.
